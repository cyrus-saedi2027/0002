# سرور نوبت آنلاین ساسان کلینیک

سروری کوچک و بدون وابستگی (فقط Node.js نسخه‌ی ۱۸ به بالا) برای:

- فرستادن فایل‌های سایت (پوشه‌ی `site/`)
- فرستادن کد تأیید ۵ رقمی با متد **Verify** سامانه‌ی sms.ir
- بررسی کد و ثبت **درخواست** نوبت (بیمار فقط بخش و نوع مراجعه را می‌گوید؛ روز، ساعت و پزشک را پذیرش تلفنی هماهنگ می‌کند)
- ثبت درخواست تماس
- **پنل پذیرش (ویزیتور)** در نشانی `/panel/`: ورود کارکنان، صف تماس، نوبت‌دهی، تقویم، پیامک تأیید نوبت و یادآوری خودکار (بخش «پنل پذیرش» پایین)

وقتی سایت از این سرور باز شود، سرور متای `sasan-api` را به صفحه اضافه می‌کند. کپسول نوبت از روی همین متا می‌فهمد سرور هست و کد را واقعاً پیامک می‌کند.

روی میزبانی ساده و بدون سرور، کپسول به‌شکل نمایشی کار می‌کند: کد روی صفحه نشان داده می‌شود و هیچ پیامکی فرستاده نمی‌شود.

## تست با گوشی خودتان (پیامک واقعی)

برای پیامک واقعی **سرور لازم است**، چون کلید sms.ir نباید در مرورگر باشد. ولی لازم نیست هاست بخرید؛ کامپیوتر خودتان همان سرور است.

1. **Node.js** (نسخه‌ی LTS) را از nodejs.org نصب کنید.
2. کل پروژه را روی کامپیوتر بیاورید (از GitHub: Code ← Download ZIP) و باز کنید.
3. **ویندوز:** در پوشه‌ی `server` روی `start-windows.cmd` دوبار بزنید.
   **مک یا لینوکس:** در ترمینال: `cd server` و بعد `npm run setup` و بعد `npm start`.
4. در پرسش‌وپاسخ:
   - حالت را **۲ (اصلی)** بزنید. در حالت آزمایشی (Sandbox) هیچ پیامکی به گوشی نمی‌رسد.
   - کلید اصلی پنل را وارد کنید. کلید موقع نوشتن ستاره نشان داده می‌شود.
   - شناسه‌ی قالب را خالی بگذارید تا قالب کد تأیید همان‌جا در پنل ثبت شود.
5. قالب باید اول **تأیید** شود (معمولاً چند ساعت). وضعیتش را با `npm run check` ببینید.
6. بعد از تأیید: `npm start`، سایت را در `http://127.0.0.1:8080` باز کنید، «نوبت بگیرید» بزنید و شماره‌ی خودتان را وارد کنید. کد به گوشی‌تان پیامک می‌شود.

- اگر در setup به «از گوشی هم باز کنید؟» بله بگویید، سایت از گوشیِ همان وای‌فای هم باز می‌شود (نشانی‌اش هنگام اجرا چاپ می‌شود).
- کد ۲ دقیقه اعتبار دارد. «ارسال دوباره» هم دقیقاً بعد از همین ۲ دقیقه باز می‌شود.

## راه‌اندازی دستی

```bash
cd server
npm run setup           # پرسش‌وپاسخ و ساخت server/.env (یا: cp .env.example .env و نوشتن دستی)
npm run check           # بررسی کلید، اعتبار پنل و وضعیت قالب
npm test                # آزمون‌ها، بدون شبکه
npm start               # http://127.0.0.1:8080
```

### ترتیب پیشنهادی

1. **آزمایشی:** `SMSIR_MODE=sandbox` و کلید Sandbox.
   - پیامک واقعی فرستاده نمی‌شود و اعتباری کم نمی‌شود.
   - کد در لاگ سرور چاپ می‌شود، مثلاً `[sandbox] کد 0912***4567: 42715`.
2. **قالب اصلی:** `npm run setup` قالب کد تأیید را در پنل ثبت می‌کند (یا در پنل بسازید؛ متن نمونه در `.env.example`). منتظر تأییدش بمانید.
3. **اصلی:**
   - `SMSIR_MODE=live`
   - `SMSIR_API_KEY`
   - `SMSIR_TEMPLATE_ID`
   - `OTP_SECRET` (دست‌کم ۳۲ نویسه)
   - در حالت اصلی، کد هیچ‌جا چاپ نمی‌شود.

## پنل پذیرش (ویزیتور)

نشانی: `http://127.0.0.1:8080/panel/` (روی سرور: `https://دامنه/panel/`). پنل از سایت پیوندی ندارد؛ نشانی را فقط به کارکنان بدهید.

### اولین بار

```bash
cd server
npm run user            # ساخت اولین حساب پذیرش: نام کاربری، نام، موبایل، رمز
npm start               # بعد /panel/ را باز کنید
```

- بقیه‌ی همکاران را هر کسی که حساب دارد از خود پنل، بخش «کارکنان»، می‌سازد. رمزی که برای همکار ساخته می‌شود موقت است و او در اولین ورود رمز خودش را می‌گذارد.
- `npm run user -- list` فهرست کارکنان، `npm run user -- reset` رمز تازه (مثلاً اگر همه رمزشان را فراموش کردند).

### ورود

- نام کاربری و رمز، بعد **کد ۵ رقمی پیامکی** به موبایل همان کارمند (همان قالب کد تأیید سایت).
- صفحه‌ی ورود یک صحنه‌ی متحرک دارد (هسته‌ی کلینیک با ضربان، سه بخش در مدار و چهار کارت که یک روز پذیرش را تعریف می‌کنند: درخواست، نوبت، پیامک، پذیرش) و زیر فرم راهنمای کوتاه: کد پیامکی چیست و حساب یا رمز تازه را از کجا بگیرید. روی گوشی همان صحنه کوچک‌تر، بالای فرم است.
- در حالت آزمایشی (Sandbox) کد ورود در لاگ سرور چاپ می‌شود.
- فقط برای آزمایش روی کامپیوتر خودتان می‌شود کد پیامکی را با `PANEL_2FA=0` خاموش کرد؛ روی سرور واقعی خاموشش نکنید.

### یک نقش: پذیرش

از دور هجدهم پنل فقط یک نوع حساب دارد: **پذیرش**. هر همکاری که حساب دارد به همه‌ی بخش‌ها دسترسی دارد: پیشخوان، درخواست‌ها، تقویم، تماس‌ها، پیامک، مقاله‌ها، آمار بازدید، کارکنان و گزارش کارها. پنل‌های جدای مدیر و پزشک برداشته شدند.

- هر همکار حساب خودش را دارد و هر کارش با نام خودش در «گزارش کارها» می‌نشیند؛ حساب مشترک نسازید.
- کسی حساب خودش را نمی‌تواند غیرفعال کند و رمز خودش را فقط از «تغییر رمز» عوض می‌کند؛ دست‌کم یک حساب فعال همیشه می‌ماند.
- حساب‌های قدیمی با نقش مدیر یا پزشک خودکار پذیرش می‌شوند و چیزی لازم نیست.

### کار روزانه در پنل

پنل در دور هفدهم از نو طراحی شد تا در نگاه اول معلوم باشد «الان چه کاری باید کرد»: بالای صفحه چهار زبانه (پیشخوان، درخواست‌ها، تقویم، تماس‌ها) و «بیشتر» (پیامک، کارکنان، گزارش کارها)؛ روی موبایل همین‌ها پایین صفحه‌اند و دکمه‌ی گرد «+» نوبت تازه می‌سازد.

- **پیشخوان:** یک جمله‌ی خلاصه («۳ نفر منتظر تماس‌اند و امروز ۵ نوبت داریم»)، حلقه‌ی نوبت‌های انجام‌شده‌ی امروز و چهار عدد (منتظر تماس، نوبت‌های امروز، در کلینیک، نوبت‌های فردا).
  - **کارهای الان:** درخواست‌های سایت، نوبت‌های تلفنی بی‌زمان و درخواست‌های تماس در یک صف، قدیمی‌ترین اول؛ حلقه‌ی کنار هر کارت نشان می‌دهد چقدر منتظر مانده (بعد از ۴ ساعت قرمز). دکمه‌های «جواب نداد»، «تماس گرفتم» و «نوبت بده» روی خود کارت‌اند.
  - **برنامه‌ی امروز:** نوبت‌ها به ترتیب ساعت با خط «الان»؛ «آمد» (بیمار در کلینیک) و بعد «انجام شد»، و برای نوبتی که بیش از ۲۰ دقیقه از ساعتش گذشته «نیامد». فهرست فردا زیرش.
- **هر درخواست** (با زدن روی کارت): پنج قدم ثبت ← تماس ← نوبت ← آمد ← انجام، و فقط «قدم بعد» با دکمه‌های همان قدم:
  - منتظر تماس: شماره‌ی بزرگ برای تماس، «تماس گرفتم»، «جواب نداد» (شمرده می‌شود) یا «همین حالا نوبت بده»
  - تماس گرفته شد: انتخاب روز و ساعت همان‌جا باز است: پزشک، نوار ۲۸ روز پیش رو (تعطیل‌ها و روزی که ساعت کاری‌اش تمام شده مشخص‌اند، نقطه = نوبت دارد)، ساعت‌ها در گروه‌های صبح، بعدازظهر، عصر و شب (ساعت پر خط‌خورده)، خلاصه‌ی انتخاب و پیامک تأیید
  - نوبت دارد: بلیت نوبت، «آمد»، «تغییر زمان»، «نیامد»، «پیامک تأیید دوباره»، «لغو نوبت»
  - در کلینیک: «درمان انجام شد»
  - یادداشت پذیرش خودکار ذخیره می‌شود؛ مراجعه‌های دیگر همین شماره، پیامک‌ها با وضعیت رسیدن و تاریخچه‌ی کارها (چه کسی، کی) هم همین‌جاست.
- هر تغییر وضعیت یک پیام کوتاه با دکمه‌ی **«برگرداندن»** دارد (مثلاً اگر «انجام شد» اشتباهی زده شد).
- **درخواست‌ها:** فیلتر منتظر پیگیری، نوبت دارند، انجام شد، لغو و نیامد، همه؛ فیلتر بخش؛ مسیر پنج‌قدمی هر درخواست کنار آن. جست‌وجوی نام، موبایل یا کد پیگیری (کلید `/`) همیشه در همه‌ی درخواست‌هاست.
- **نوبت تازه** (دکمه‌ی بالا یا کلید `N`) در سه قدم: بیمار (اگر شماره پرونده‌ی قبلی دارد خبر می‌دهد) ← بخش و نوع مراجعه ← زمان: «روز و ساعت را همین حالا انتخاب می‌کنم»، «همین حالا در کلینیک است» (پذیرش فوری بدون نوبت قبلی) یا «بعداً هماهنگ می‌کنم».
- **تقویم:** هفته‌ی شنبه تا جمعه با فیلتر بخش و پزشک، روزهای تعطیل هاشورخورده و «+» برای نوبت تازه در همان روز؛ روی موبایل نوار روزها و برنامه‌ی همان روز. قابل چاپ.
- **تماس‌ها:** فرم «با من تماس بگیرید» سایت؛ «تماس گرفتم»، «انجام شد» یا «ثبت نوبت» (نوبت تازه با نام و شماره‌ی همین درخواست).
- **پیامک:** اعتبار پنل sms.ir، حالت ارسال، تعداد فرستاده‌ها، قالب‌های روشن و خاموش، و همه‌ی پیامک‌ها با وضعیت رسیدن.
- **کارکنان** و **گزارش کارها** (گزارش به تفکیک روز).
- پنل هر ۳۰ ثانیه تازه می‌شود؛ کارت‌ها بدون پرش سر جای تازه‌شان می‌لغزند و درخواست تازه‌ی سایت با پیام کوتاه، عدد روی زبانه و درخشش کارت خبر داده می‌شود. اگر اتصال قطع شود، نشان «اتصال قطع است» بالای صفحه می‌آید.
- اگر دو نفر هم‌زمان یک درخواست را تغییر دهند، کار دومی رونویسی نمی‌شود: پنل نسخه‌ی تازه را نشان می‌دهد تا دوباره تصمیم بگیرد.
- وضعیت «در کلینیک» (`arrived`) فقط برای نوبتی که روز و ساعت دارد پذیرفته می‌شود.

### پیامک‌های پنل (اختیاری، قالب نوع ۲ «اطلاع‌رسانی»)

`npm run setup` در حالت اصلی می‌پرسد این دو قالب را هم در پنل sms.ir بسازد؛ بعد از تأیید کارشناسان sms.ir روشن می‌شوند. پارامترها `NAME`، `DEPT`، `DATE` (مثلاً «شنبه ۱۲ مهر») و `TIME` (مثلاً «۱۰:۳۰») هستند.

| متغیر | کار |
|---|---|
| `SMSIR_APPT_TEMPLATE_ID` | تأیید نوبت (وقتی پذیرش نوبت می‌دهد و تیک پیامک را می‌زند) |
| `SMSIR_REMIND_TEMPLATE_ID` | یادآوری خودکار یک روز قبل از نوبت |
| `SMSIR_REMIND_HOUR` | ساعت شروع ارسال یادآوری‌ها به وقت تهران (پیش‌فرض ۱۷؛ تا ۲۱:۳۰ فرستاده می‌شوند) |

- یادآوری برای نوبت لغوشده فرستاده نمی‌شود و اگر زمان نوبت عوض شود، یادآوری تازه برای زمان تازه می‌رود.
- یادآوری ناموفق تا ۳ بار دوباره امتحان می‌شود.

### امنیت پنل

- **رمزها:** فقط هش scrypt با نمک تصادفی در `data/users.json`.
  - رمز ساده، کوتاه یا شامل نام کاربری پذیرفته نمی‌شود.
  - بعد از ۵ رمز اشتباه، ورود با آن حساب ۱۵ دقیقه بسته می‌شود.
- **نشست:** کوکی `HttpOnly` و `SameSite=Strict` (روی HTTPS با `Secure`) فقط برای `/api/panel`.
  - سرور فقط هش شناسه‌ی نشست را نگه می‌دارد.
  - نشست با ۴ ساعت بی‌کاری یا ۱۲ ساعت بعد از ورود تمام می‌شود.
  - با عوض شدن رمز یا غیرفعال شدن حساب، همه‌ی نشست‌های آن کاربر فوراً باطل می‌شوند.
- **درخواست‌ها:** هر درخواست تغییر، سربرگ `x-sasan-panel` و مبدأ همین سایت را لازم دارد (در برابر CSRF).
- **صفحه‌ی پنل:**
  - CSP سخت‌گیر: بدون اسکریپت و استایل درون‌خطی و بدون قاب.
  - بدون کش، و `noindex` برای موتورهای جست‌وجو.
- **گزارش کارها:** همه‌ی کارها در `data/audit.jsonl` ثبت می‌شوند؛ رمز، کد تأیید و متن پیامک هیچ‌وقت در آن نمی‌آیند.
- **آمار بازدید سایت:** هر صفحه‌ی سایت یک بار `POST /api/hit` می‌فرستد (نشانی صفحه، دامنه‌ی سایت قبلی، پهنای صفحه). سرور فقط شمارنده‌های روزانه را در `data/stats.json` نگه می‌دارد؛ IP و مرورگر فقط برای شمردن «بازدیدکننده‌ی یکتای امروز» با نمکی که هر روز عوض می‌شود درهم‌سازی و در حافظه نگه داشته می‌شوند و هرگز ذخیره نمی‌شوند. ربات‌ها شمرده نمی‌شوند؛ «ردیابی نکن» مرورگر رعایت می‌شود؛ ۴۰۰ روز آخر می‌ماند.
- **پزشک:** شماره‌ی بیمار و پیامک‌ها را اصلاً از سرور دریافت نمی‌کند.

### API پنل (همه با کوکی نشست)

| مسیر | کار |
|---|---|
| `POST /api/panel/login`، `login/code`، `login/resend`، `logout` | ورود دو مرحله‌ای و خروج |
| `GET /api/panel/me`، `POST /api/panel/password` | کاربر، تنظیمات، تغییر رمز |
| `GET`، `POST /api/panel/bookings` | فهرست و نوبت تلفنی |
| `PATCH /api/panel/bookings/:ref` | `{ v, status, date, time, doctor, staffNote, noAnswer, sms }`؛ `v` نسخه‌ای است که کارمند دیده (ناهمخوانی = 409) |
| `POST /api/panel/bookings/:ref/sms`، `…/sms/refresh` | پیامک تأیید دوباره، به‌روزرسانی وضعیت رسیدن |
| `GET /api/panel/callbacks`، `PATCH …/:id` | درخواست‌های تماس |
| `GET /api/panel/sms`، `POST /api/panel/sms/refresh` | اعتبار، قالب‌ها و گزارش پیامک‌ها |
| `GET`، `POST /api/panel/users`، `PATCH …/:id` | کارکنان |
| `GET /api/panel/audit` | گزارش کارها |
| `GET /api/panel/stats?days=30` | آمار بازدید سایت: بازدیدکننده و بازدید روزانه، صفحه‌های پربازدید، منبع ورود و دستگاه |

## API

| مسیر | کار |
|---|---|
| `GET /api/health` | وضعیت سرور و حالت پیامک |
| `POST /api/otp/send` | بدنه: `{ mobile }`. پاسخ: `{ ok, ttl: 120, resend: 120 }` |
| `POST /api/booking` | بدنه: `{ mobile, code, name, note, dept, type }`. پاسخ: `{ ok, ref }`. روز، ساعت و پزشک از بیمار گرفته نمی‌شود |
| `POST /api/callback` | بدنه: `{ name, mobile, topic }` |
| `GET /api/bookings?status=new` | فقط با `Authorization: Bearer ADMIN_TOKEN` |
| `PATCH /api/bookings/:ref` | پذیرش بعد از تماس. بدنه: `{ status, date, time, doctor, staffNote }` (هر کدام اختیاری). وضعیت‌ها: `new`، `called`، `scheduled`، `done`، `cancelled`، `no-show`. `time` دقیقه از نیمه‌شب است (مثلاً ۶۳۰ یعنی ۱۰:۳۰) |
| `GET /api/callbacks` | فقط با توکن مدیریت |

خطاها همیشه به شکل `{ ok: false, error }` برمی‌گردند. مقدارهای `error`:

- `mobile`
- `rate` (همراه `wait` به ثانیه)
- `sms`
- `input`
- `code` (همراه `left`)
- `expired`
- `attempts`
- `many` (این شماره هنوز درخواست پیگیری‌نشده دارد)

## نکته‌های امنیتی که رعایت شده

- **کلیدها:**
  - کلیدها فقط از متغیرهای محیطی یا `server/.env` خوانده می‌شوند و هیچ‌وقت چاپ نمی‌شوند.
  - کلید فقط در سربرگ `x-api-key` فرستاده می‌شود، نه در آدرس.
- **کد تأیید:**
  - کد با `crypto.randomInt` ساخته می‌شود.
  - فقط هش HMAC آن در حافظه می‌ماند و مقایسه با `timingSafeEqual` انجام می‌شود.
  - هر کد ۲ دقیقه اعتبار دارد، ارسال دوباره فقط بعد از تمام شدن همین ۲ دقیقه ممکن است، هر کد ۵ بار امتحان می‌شود و یک‌بارمصرف است.
- **محدودیت ارسال:**
  - هر شماره: ۵ بار در ساعت و ۱۰ بار در روز.
  - هر آی‌پی: ۱۰ بار در ۱۰ دقیقه و ۴۰ بار در روز.
  - کل سرور: ۳۰۰ بار در ساعت، تا اعتبار پنل با حمله خالی نشود.
- **ورودی‌ها:**
  - بدنه فقط JSON و حداکثر ۸ کیلوبایت است.
  - درخواست‌های POST از دامنه‌ی دیگر رد می‌شوند.
  - متن‌ها پاک‌سازی می‌شوند.
  - هر شماره حداکثر دو درخواست پیگیری‌نشده می‌تواند داشته باشد.
  - روز، ساعت و پزشک فقط از پنل پذیرش (با توکن مدیریت) ثبت می‌شود.
- **سربرگ‌ها و فایل‌ها:**
  - سربرگ‌های امنیتی فرستاده می‌شوند: CSP، nosniff، X-Frame-Options، Referrer-Policy و Permissions-Policy.
  - مسیر فایل‌ها در برابر `../` محافظت شده است.
- **داده‌ها:**
  - نوبت‌ها در `server/data/bookings.json` با دسترسی 600 ذخیره می‌شوند؛ کارکنان، نشست‌ها و گزارش کارهای پنل هم در همین پوشه (`users.json`، `sessions.json`، `audit.jsonl`).
  - این پوشه در `.gitignore` است. از آن پشتیبان منظم بگیرید (راهنما: `DEPLOY.md`).
  - برای پنل مدیریت و حجم بالا، بعداً می‌شود ذخیره را به پایگاه داده (مثلاً SQLite) برد.

## اجرای دائمی (نمونه)

- پشت Nginx با HTTPS اجرا کنید و `TRUST_PROXY=1` و `HSTS=1` بگذارید.
- با `pm2` یا `systemd` اجرا کنید تا بعد از ری‌استارت سرور خودش بالا بیاید.
- در پنل sms.ir کلید اصلی را به آی‌پی همین سرور محدود کنید.
