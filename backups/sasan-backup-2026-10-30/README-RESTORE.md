## ۱. بکاپ زنده‌ی سرور (اول از همه)

با PuTTY به `root@89.44.243.30` وصل شوید (رمز در `SECRETS.txt`) و این یک خط را بچسبانید. این دستور اول کد تازه را می‌گیرد، چون `backup.sh` در نسخه‌ی جدید است:

```bash
true; cd /srv/sasan && git fetch -q --depth 1 origin claude/stoic-brahmagupta-1np5fy && git reset -q --hard FETCH_HEAD && bash server/deploy/backup.sh; true
```

آخر کار می‌نویسد چند نوبت و مخاطب و حساب و عکس در بکاپ رفت، و نشانی فایل را می‌دهد، مثلاً `/root/backups/sasan-server-backup-2026-10-31_0200.tgz`.

**گرفتن فایل روی کامپیوتر** (VPN خاموش):
- **ویندوز:** در PowerShell یا cmd، داخل پوشه‌ای که می‌خواهید فایل در آن بیاید: `pscp root@89.44.243.30:/root/backups/نام-فایل.tgz .`
  (`pscp` همراه PuTTY است.)
- **یا WinSCP:** پروتکل SFTP، سرور `89.44.243.30`، کاربر `root` ← پوشه‌ی `/root/backups` ← فایل را بکشید.
- بعد از دانلود، حجم فایل را با سرور مقایسه کنید (چند صد کیلوبایت تا چند مگابایت) و یک نسخه‌ی دیگر هم جای دیگری بگذارید.

این فایل شامل **شماره‌ی بیمارها، `.env` (کلید sms.ir) و کلید خصوصی HTTPS** است. اگر قرار است در ابر یا فلش بماند، رمزگذاری کنید:

```bash

```

(خروجی `.tgz.enc` می‌شود؛ عبارت را گم نکنید، بدونش باز نمی‌شود.)

سرور هر شب ساعت ۳:۱۵ هم خودش از `data/` در `/var/backups/sasan` بکاپ می‌گیرد (۳۰ روز)، ولی آن‌ها روی همان سرورند و با تمام شدن اشتراک از دست می‌روند.

## ۲. بالا آوردن روی سرور تازه

**پیش‌نیاز:** یک سرور Ubuntu 24.04 (یا Debian) با دسترسی root، و دو فایل: بکاپ زنده‌ی بند ۱ و (اگر گیت‌هاب در دسترس نیست) `sasan-code-2026-10-30.tar.gz`.

**الف) فایل بکاپ را به سرور تازه بفرستید:**
```
pscp نام-فایل.tgz root@آی‌پی-سرور-تازه:/root/
```

**ب) کد را بگذارید** (یکی از دو راه):

با گیت‌هاب:
```bash
apt-get update -qq && apt-get install -y -qq git
git clone --depth 1 -b claude/stoic-brahmagupta-1np5fy https://github.com/cyrus-saedi2027/0002.git /srv/sasan
```

بدون گیت‌هاب (کد همین پوشه؛ اول فایل را با `pscp` به `/root/` بفرستید):
```bash
mkdir -p /srv/sasan
tar -xzf /root/sasan-code-2026-10-30.tar.gz -C /srv/sasan --strip-components=1
```

**پ) بازگردانی با یک دستور:**
```bash
bash /srv/sasan/server/deploy/restore.sh /root/نام-فایل-بکاپ.tgz
```
(برای فایل رمزگذاری‌شده: `BACKUP_PASS='عبارت' bash /srv/sasan/server/deploy/restore.sh /root/نام-فایل.tgz.enc`)

این دستور، به‌ترتیب:
1. بکاپ را باز می‌کند و سالم بودنش را می‌سنجد؛
2. `server/data` و `server/.env` را می‌گذارد (اگر از قبل چیزی بوده، کنارش با پسوند `.before-restore-تاریخ` نگه می‌دارد، پاک نمی‌کند)؛
3. گواهی HTTPS را برمی‌گرداند، فقط اگر هنوز بیش از یک هفته اعتبار دارد؛
4. `setup.sh` را اجرا می‌کند: Node.js، nginx، سرویس `sasan`، HTTPS، بکاپ شبانه، فایروال، آزمون‌ها و بررسی نهایی.

حساب پنل با **همان نام کاربری و رمز قبلی** کار می‌کند، چون حساب‌ها هم در بکاپ بودند.

**ت) DNS:** رکوردهای دامنه را به سرور تازه ببرید (در پنل DNS دامنه، همان جایی که الان رکورد A هست):

| نوع | نام | مقدار |
|---|---|---|
| A | `@` (یعنی `sasan-clinic.ir`) | آی‌پی سرور تازه |
| A | `www` | آی‌پی سرور تازه |

اگر DNS را به جای دیگری هم منتقل می‌کنید، **رکورد تأیید Search Console** (`TXT`، با مقدار `google-site-verification=…`) را هم همان‌جا بسازید. مقدارش در Search Console ← Settings ← Ownership verification است. بدونش مالکیت سایت از دست می‌رود و آمار و سایت‌مپ قطع می‌شود.

بعد از رسیدن DNS (چند دقیقه تا چند ساعت؛ با `nslookup sasan-clinic.ir` ببینید) اگر گواهی تازه لازم بود، یک بار دیگر بزنید:
```bash
bash /srv/sasan/server/deploy/setup.sh sasan-clinic.ir
```

**ث) بررسی:**
- `curl https://sasan-clinic.ir/api/health` باید `{"ok":true,…,"mode":"live"}` بدهد.
- با VPN خاموش: سایت، پنل (`/panel/`) و ثبت یک نوبت آزمایشی با کد پیامکی.
- روی سرور: `cd /srv/sasan/server && runuser -u www-data -- node tools/sms.js check` وضعیت کلید و قالب پیامک را می‌گوید.

### اگر بکاپ زنده‌ی سرور را نداشتید

سایت و پنل بالا می‌آید، ولی **با داده‌ی خالی**: نوبت‌ها، مخاطب‌ها و مقاله‌های ساخته‌شده در پنل نیستند. بعد از گذاشتن کد (بند ب):
```bash
SMS_KEY='کلید-اصلی-sms.ir' PANEL_PASS='رمز-قوی-پنل' bash /srv/sasan/server/deploy/install.sh
```
(کلید و رمز آماده در `SECRETS.txt` است.)

## ۶. چه چیزی آزمایش شد و چه چیزی نه

**آزمایش‌شده، با نتیجه:**
- کد بسته‌ی `sasan-code-…tar.gz` باز شد: ۲۴ آزمون قبول، سرور بالا آمد و صفحه‌های اصلی، خدمات، پزشکان، تماس، سایت‌مپ، پنل و راهنمای پنل `200` دادند. در فایل چیزی از رمزها و کلیدها نیست.
- `.bundle` کلون شد: همان کامیت و همان درخت فایل‌های بسته‌ی کد.
- `backup.sh` و `restore.sh` روی یک سرور ساختگی که با کد خود پروژه پر شد (۳ نوبت، ۱ تماس، ۴ مخاطب، حساب پنل، عکس پنل، `.env` و گواهی): داده و `.env` بایت‌به‌بایت یکسان برگشت؛ نسخه‌ی بازگردانده‌شده بالا آمد، با **همان رمز قبلی** وارد پنل شد، نوبت‌ها و مخاطب‌ها را دید و عکس بارگذاری‌شده را نشان داد؛ رمزگذاری با عبارت درست باز شد و با عبارت غلط رد شد؛ گواهی کم‌اعتبار (کمتر از یک هفته) بازگردانده نشد.

**آزمایش‌نشده:**
- `backup.sh` هنوز **روی سرور واقعی اجرا نشده**، چون از جایی که این بکاپ ساخته شد به سرور ایران دسترسی نبود. دستورش در بند ۱ است. اگر خطایی دیدید، خروجی را بفرستید.
- اجرای `setup.sh` (apt، nginx، certbot) روی یک سرور تازه در این آزمایش نبود؛ همین `setup.sh` روی سرور واقعی چند بار اجرا شده و `restore.sh` فقط داده و گواهی را پیش از آن می‌گذارد.
- حساب‌های بیرونی (Search Console، Bing، گوگل‌مپ، بلد، نشان، sms.ir) به این فایل‌ها بستگی ندارند و با تغییر سرور عوض نمی‌شوند، به‌جز رکورد DNS تأیید که بالا گفته شد.
